# Minecraft 原版下载器 1.2.1

独立的 **Minecraft Java 版原版下载工具**，面向 Windows x64，仅依赖 Python 3.10+ 标准库和 Tk。
从 Mojang 官方清单下载游戏文件，支持增量补全与实例包导出，不依赖某一款启动器。

下载结果采用通用的 `.minecraft` 游戏目录布局，导出包采用 MultiMC 实例格式。
支持对应目录布局或导入格式的启动器都可以作为目标启动器，HMCL 只是其中一种选择。
本工具负责准备游戏文件；游戏启动、Java 运行时选择和账号登录由你使用的启动器处理。

## 启动器兼容方式

| 目标启动器提供的功能 | 使用方式 |
| --- | --- |
| 支持标准 `.minecraft` 游戏目录 | 把下载完成的 `.minecraft` 添加为已有游戏目录，或直接选中原有 `.minecraft` 增量下载 |
| 支持 MultiMC 格式实例包 | 导入本工具生成的 ZIP，由启动器创建和管理实例 |
| 使用自己的实例、缓存或配置结构 | 按该启动器的导入、迁移方式操作，不能仅凭目录相似认定可以直接使用 |

**目录结构相近不代表所有启动器都能以同一种方式识别游戏。**
游戏目录识别、实例注册、缓存位置和支持的导入格式可能不同；本项目不承诺所有启动器直接兼容，
也不承诺导入后完全不需要联网补文件。

## 使用

1. 双击 `start.cmd`，或执行 `python app.py`。
2. 等待官方版本列表加载，选择版本；可搜索、显示快照或远古版本。
3. 选择保存目录、代理模式和并发数。
4. 按需勾选“完成后导出 MultiMC 实例 ZIP”，点击“开始下载”。
5. 完成后点击“打开游戏目录”，再按上面的兼容方式添加目录或导入实例包。

默认使用系统代理；自定义代理接受 HTTP/HTTPS 代理 URL，不支持 SOCKS URL。
“直连”仅禁用应用层代理，不能绕过系统的 TUN、VPN 或路由。
下载失败后可重试：已有且 SHA-1 正确的文件会复用，未完成的单文件会重新下载。
取消会停止安排新任务，当前连接可能需要等待约 30 秒超时。
同一版本的输出目录有进程锁，避免两个窗口同时写入。

## 自动识别游戏目录与增量下载

保存位置的**最后一级文件夹名为 `.minecraft`**（忽略大小写）时，直接把它作为游戏根目录：

```text
所选目录/.minecraft/
  versions/<版本>/<版本>.json
  versions/<版本>/<版本>.jar
  libraries/
  assets/
  downloader-exports/Minecraft-<版本>-Windows-x64.zip
```

不会再创建 `Minecraft-<版本>/.minecraft`。已有且大小、SHA-1 正确的文件会复用，
只下载缺失或损坏的客户端、依赖库和资源；不同版本共享 `libraries`、`assets`。
旧清单没有哈希的文件仍会重新下载，以免把无法验证的内容当成有效缓存。
勾选导出时，ZIP 存入该游戏目录内的 `downloader-exports`，且只包含所选版本需要的文件。
不会把其他实例、存档、模组或账号文件打进包。

**选择普通文件夹时保持原行为**：创建 `Minecraft-<版本>/.minecraft`，ZIP 保存在所选文件夹。
是否已有 `assets`、`versions` 子目录不参与猜测，界面始终预览实际游戏路径和 ZIP 位置。

同版本 JSON 若只是排版不同会保留原文件；若内容与官方清单不同（例如已有自定义启动参数、
模组加载器或启动器专用补丁配置），会在下载前停止并提示改用独立目录。不会把已有实例改写成原版。
新版本 JSON 在全部文件下载、校验成功后才写入；失败或取消不会发布不完整的新实例。
增量模式使用整个游戏目录共用的进程锁，避免不同版本同时写共享文件。

1.2 界面采用双栏布局：左侧版本筛选，右侧下载设置，下方独立展示文件完成数、校验复用数、
本次下载量和任务阶段。日志可展开，错误时会自动显示。

1.2.1 将默认窗口缩至最多 960×660，并按 Windows 扣除任务栏后的工作区进一步缩小、居中，
为标题栏和边框预留空间。版本与设置区域可滚动，窄窗口自动上下排列；下载、取消、打开目录等
按钮固定在窗口底部，不随内容滚动。展开日志不会把操作栏挤出窗口。

如果 Mojang 清单连接出现 SSL EOF，1.1 会在 `piston-meta.mojang.com` 和
`launchermeta.mojang.com` 两个官方域名之间切换，并显示重试日志；清单哈希校验和
TLS 证书验证始终保留。系统代理模式重试时重新读取代理设置。若仍然失败，可在界面选择
“自定义 HTTP 代理”，填写本机代理的实际地址后重试。更新后需要关闭旧窗口、重新启动。

## 输出和导入

```text
downloads/
  Minecraft-<版本>/.minecraft/     # 传统游戏目录布局
  Minecraft-<版本>-Windows-x64.zip
```

ZIP 包含 `instance.cfg`、`mmc-pack.json`、完整 `.minecraft` 目录，以及文件校验清单
`download-manifest.json`。只有本次清单列出的游戏文件会入包，不会扫描和打包账户、令牌、
已有存档或其他文件。

- **实例包导入**：在支持 MultiMC 格式的启动器中选择相应的“导入实例/整合包”功能，选中 ZIP。
  使用标准 MultiMC 实例描述，只声明 `net.minecraft` 原版组件。
  **各启动器的全局缓存和导入规则不同，可能重新下载元数据、客户端、库或资源；不保证离线导入。**
  当前已完成导出包结构检查，尚未逐一验证各启动器的实际导入和游戏启动。
- **已有游戏目录**：直接使用下载目录，或解压 ZIP，将 `.minecraft` 添加到支持标准目录布局的启动器中。
  不要直接覆盖已有游戏目录；某些新版启动器会迁移旧目录结构。
- 本包只面向 Windows x64。不会下载或捆绑 Java 运行时、账号信息或启动器。
  所需 Java 主版本显示在日志和 ZIP 的说明文件中，由启动器选择或安装。
- 游戏登录与所有权验证由启动器处理。本工具只负责文件下载。

## 下载内容

从 Mojang 官方版本清单获取版本 JSON，下载客户端、按当前 Windows 环境规则筛选的库和
原生库、资源索引及资源对象、日志配置。兼容旧资源的 virtual/map_to_resources 目录。
有 SHA-1 或大小的文件按元数据校验；校验完成后原子替换目标文件。
旧版没有哈希的依赖每次重新下载。旧的可变资源索引仅在 URL 中包含清单给出的 SHA-1 时校验该哈希，
以兼容可能已更新、但元数据仍保留旧哈希的索引。
缺少资源索引或平台库元数据的旧版本会明确报错，不会声称完整下载成功。
原生库保留为原始 JAR，由启动器在启动时解压。
